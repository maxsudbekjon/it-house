# Заявки (`contact`)

Форма заявки на сайте. Эндпоинт сохраняет заявку в `ContactMessage` и отправляет уведомление в Telegram-чат администраторов.

## Эндпоинт

| Метод | URL | Доступ | Описание |
|---|---|---|---|
| `POST` | `/api/contact/` | все | Создать заявку |

- Авторизация не нужна.
- Throttle: **1 запрос в час** с одного клиента. Учитываются все запросы, в том числе те, что вернули `400`. При превышении лимита ответ `429` с заголовком `Retry-After`.
- Других методов нет: `GET` возвращает `405`.

## Запрос

```json
{
  "name": "Ali Valiyev",
  "phone_number": "+998901234567",
  "course": "Backend",
  "message": "Kechki guruh bormi?"
}
```

| Поле | Тип | Обязательно | Ограничения |
|---|---|---|---|
| `name` | string | да | до 255 символов, не пустое |
| `phone_number` | string | да | до 20 символов, формат не проверяется |
| `course` | string \| null | нет | до 255 символов, свободный текст (не id курса) |
| `message` | string \| null | нет | до 1000 символов |

- Поля `course` и `message` можно не передавать, а также передать `null` или `""`.
- Пробелы по краям строк обрезаются. Строка из одних пробелов считается пустой.

## Ответ `201`

Возвращается созданная заявка:

```json
{
  "id": 42,
  "name": "Ali Valiyev",
  "phone_number": "+998901234567",
  "course": "Backend",
  "message": "Kechki guruh bormi?",
  "created_at": "2026-10-10T09:40:00.123456+05:00"
}
```

## Ошибки

`400`: ошибки валидации по полям:

```json
{"message": ["Ensure this field has no more than 1000 characters."]}
```

`429`: превышен лимит запросов:

```json
{"detail": "Request was throttled. Expected available in 3599 seconds."}
```

Важно для фронтенда: запрос с ошибкой `400` тоже расходует лимит. Повторная отправка после исправления получит `429` и будет заблокирована на час. Поэтому ограничения полей (`maxlength`, обязательность) нужно проверять на клиенте до отправки.

## Уведомление в Telegram

```
New Contact Message:
Name: Ali Valiyev
Phone Number: +998901234567
Course: Backend
Message: Kechki guruh bormi?
```

- Строка `Message:` добавляется, только если текст не пустой.
- Текст передаётся без `parse_mode`, поэтому HTML и Markdown из заявки не интерпретируются.
- Настройки берутся из `.env`: `BOT_TOKEN`, `ADMIN_CHAT_ID`.
- Если Telegram недоступен или отвечает ошибкой, заявка всё равно сохраняется и клиент получает `201`. Таймаут запроса к Telegram 5 секунд. Ошибка пишется в лог контейнера; токен бота в лог не попадает:

```bash
docker logs ithouseedu_backend 2>&1 | grep "Telegram sendMessage failed"
```

## Известные ограничения

- `ContactMessage` не зарегистрирован в админке, поэтому заявки видны только в Telegram и в базе.
- Счётчик throttle хранится в памяти каждого воркера gunicorn (их 4) и сбрасывается при перезапуске контейнера. Поэтому реальный лимит может доходить до 4 заявок в час.
